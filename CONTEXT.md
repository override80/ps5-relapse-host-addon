# PS5 Relapse Exploit Host — context

Self-contained host for the Relapse PS5 exploit chain (firmware 7.00–13.60)
plus the payload/pin tools. Runs as a Home Assistant addon on the hassio
server (10.11.12.98) with `host_network: true`.

## Layout

```
ps5-exploit-host/
├── config.yaml            # HA addon manifest (host_network: true)
├── Dockerfile             # python:3.9-slim + openssl, builds from app/
├── run.sh                 # direct (non-Docker) run: sudo ./run.sh
├── CONTEXT.md             # this file
├── app/
│   ├── entrypoint.sh      # generates self-signed cert, starts server on 8082/8444
│   └── relapse/           # served root (the exploit site)
│       ├── serve_tls.py   # HTTP+HTTPS server, no-store headers, deep-path mapping
│       ├── index.html, src/, offsets/ (7.00-13.60), payloads/
│       └── cert.pem/key.pem  # generated at start (self-signed, CN=manuals.playstation.net)
└── tools/
    ├── send_payload.py            # send an ELF to elfldr on the PS5 (port 9021)
    ├── shsrv-ps5.elf              # shell server payload (listens on PS5 port 2323)
    ├── elfldr-ps5-generic.elf     # fallback loader if the bundled 1360 elf fails
    └── ps5-firmware-pin/          # lvndry/ps5-firmware-pin (pin/unpin scripts)
```

## Network design (pfSense 10.11.12.254) — see PLAN.md (current design)

- DNS host override: `manuals.playstation.net` -> **10.11.12.98** (hassio).
  No VIP, no NAT on pfSense.
- DNS domain override: `update.playstation.net` -> 127.0.0.2 (blocks all Sony
  firmware update servers; verified: deu01.ps5.update.playstation.net etc. fail)
- PS5: 10.11.12.74 (DHCP reservation for MAC b4:1f:4d:f2:84:f8; it used
  10.11.12.28 when manually set, .74 after a reboot)
- hassio nginx addon (core_nginx_proxy) serves a custom server block for
  manuals.playstation.net (self-signed cert in /ssl/) and proxies to the
  Relapse addon on host port 8082.

## Why nginx fronts it

`core_nginx_proxy` (NGINX Home Assistant SSL proxy 4.5.3) owns host ports
80/443 via Docker port mapping (host_network: false, container 172.30.33.8).
It supports custom server blocks via `customize.active: true`
(`/share/nginx_proxy/*.conf`), so we add a `server_name manuals.playstation.net`
block there instead of touching pfSense NAT.

## Certificate note

The cert is **self-signed for manuals.playstation.net** (generated by
entrypoint.sh at container start). The PS5 User's Guide shows an
untrusted-certificate prompt — accept it. The `core_letsencrypt` addon
(6.5.0) is installed but **stopped** and not needed: manuals.playstation.net
is Sony's domain and can never get a publicly-trusted cert.

## Install the addon

```bash
ssh hassio 'cp -r /tmp/tools/new/ps5-exploit-host /addons/'
# then in HA: Settings > Add-ons > Add-on Store > ⋮ > Check for updates
# the addon appears under "Local add-ons" -> install -> start
```

Verify from any LAN machine: `curl -k https://10.11.99.254/` should return
the `PS5-Relapse` page.

## Per-boot routine (jailbreak is tethered)

1. PS5 boots -> wait 30-60 s idle (13.40 is flaky; improves success a lot)
2. PS5: Settings > Guide and Tips, Health and Safety, Other Information >
   User's Guide -> accept cert prompt -> wait for
   `elfldr is listening on port 9021`
   (if it says `unexpected oid state` / hangs at `checking aio groups`:
   hard-reset the PS5 — hold power ~10 s — and retry)
3. From a computer on the LAN:
   ```bash
   nc -z -w 4 10.11.12.74 9021 && echo OPEN || echo CLOSED
   python3 tools/send_payload.py 10.11.12.74 9021 tools/shsrv-ps5.elf
   nc -z -w 4 10.11.12.74 2323 && echo OPEN || echo CLOSED
   cd tools/ps5-firmware-pin && python3 pin/ps5-fw-pin.py --host 10.11.12.74
   ```
4. PS5: Settings > System > System Software and Updates > Automatic
   Downloads > System Software and Apps > Off. Never confirm an update
   screen — press X.

## Rollback

- pfSense: delete the 2 NAT port forwards, the 10.11.99.254 VIP, and the
  DNS overrides (Services > DNS Resolver)
- PS5: `python3 pin/ps5-fw-unpin.py --host 10.11.12.74`
- Stop/remove the addon in HA
